# web_search — 检索证据库

存放联网检索（web search / 官方文档查询 / 资料调研）的**过程记录与关键证据**。

## 定位：证据，不是结论

| 目录 | 放什么 |
| --- | --- |
| `docs/web_search/` | **过程**：查询词、来源、摘录、检索时间、采用与否 |
| `docs/specs/` | **结论**：为什么这么定、最终方案是什么 |

结论里引用的每条依据，都应该能在这里反查到原始记录。

## 为什么要有它

- Agent 的检索结果默认只活在上下文里，**会话一结束就蒸发**，下次重头再搜一遍
- 验收时「这个结论哪来的」无法追溯，只能靠记忆背书
- 链接会失效，**只存 URL 等于没存**
- 调研过的方案被否掉了，不留记录就会有人重复调研

## 谁写

任何 Agent 都可写**自己的**检索记录；主理人验收时抽查引用是否成立。

## 命名

```
YYYYMMDD-<主题>.md
```

一个主题一份文件（同主题多轮检索追加到同一份），不做「一天一大杂烩」。
示例：`20261119-宽宏项目数据源调研.md`

## 单份记录的结构

```markdown
# <检索主题>

- 检索人：<主理人 / Agent 名>　会话 ID：`sess_xxx`
- 检索时间：2026-11-19 14:20
- 引擎 / 渠道：brave / context7 / 官方文档 / 站内搜索
- 查询词：`<实际输入的关键词>`

## 结论（可直接被引用）

> 一句话说清这次检索得到了什么可用的东西；没有结论就写「未得可用结论」

## 证据

| # | 来源 | 链接 | 摘录 | 采用 |
| --- | --- | --- | --- | --- |
| 1 |  |  |  | ✅ 采用 / 👁 参考 / ❌ 否掉 |

## 否掉的理由

> 否掉的方案必须写原因，否则下次还会有人重查一遍
```

## 三条硬规矩

1. **存摘录，不只存链接**：链接会死，摘录不会
2. **写明引擎与查询词**：别人要能用同样的查询复现同样的结果
3. **标注采用情况**：`采用` / `参考` / `否掉` 三选一，`否掉` 必须写理由

## 生命周期

- 检索记录**长期保留**（它是证据，与 `temp_text/` 的草稿性质不同）
- 未形成结论、也从未被引用的记录，**7 天后**可清理
- 同一主题的记录超过 5 条 → 说明该收敛了：整理成一份调研结论，写进 `docs/specs/`

## 红线

- 不把检索记录当最终结论（结论在 `docs/specs/`）
- 不整段粘贴原文，存摘录 + 链接 + 自己的判断
- 不记录含个人信息、密钥、内部机密的结果
