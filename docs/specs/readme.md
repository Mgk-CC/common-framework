# specs — 项目规格文档目录

本目录存放项目的**规格与记忆类文档**，是主理人（Manager Agent）与各 Subagent 的共同依据。

## 文档组成

| 文件 | 作用 | 谁维护 |
| --- | --- | --- |
| `项目总方案以及框架.md` | 项目的总体规划与技术框架：目标、范围、架构设计、技术选型、模块划分、关键约定 | 主理人 |
| `项目进度.md` | 按日期与模型记录的执行流水：谁、在什么时间、完成了什么、对应哪个会话 | 主理人 / Subagent（均须按本文格式） |
| `memory.md` | 踩坑记录与固化记忆：踩过的坑、结论、以及后续必须遵守的经验条目 | 主理人 / 各 Agent 提交，主理人归档 |

## 协作模式

日常工作流基于 **herdr**：

1. 主理人负责拆解整个项目、编写计划、验收成果。
2. 主理人按计划并行开启若干 **Subagent** 执行具体任务。
3. Subagent 执行完毕后，**同样可以写入 `项目进度.md`**，但必须严格套用本文的格式规范，不得自创结构。
4. 主理人负责最终把关：校验 subagent 写入的条目格式是否合规、日期与模型分类是否归位正确。

## `项目进度.md` 编写规范

> **格式的权威定义在根目录 `README.md` 的「规则细则 → `项目进度.md` 格式」一节**，本文件提供完整示例。两者若不一致，以 `README.md` 为准。

- **写入方**：主理人与 Subagent 均可写入，但格式必须与本规范完全一致，严禁自创结构。
- **两级分类**：先按日期分组（`## YYYY-MM-DD`），再按模型分组（`### 模型名`）；目标小节已存在则追加，不存在则新建。
- **条目格式**：编号小节 + 完成内容 + 时间 + 会话 ID，四项缺一不可。
- **只追加不覆写**：不得修改或删除他人已写入的条目；发现格式错误时上报主理人统一订正。

格式示例：

```markdown
## 2026-11-19

### deepseek-v4.1-flash

1. 完成项目骨架目录结构搭建
   - 时间：14:05
   - 会话 ID：`sess_20261119_1405_ab12`
2. 完成文档目录初始化
   - 时间：14:32
   - 会话 ID：`sess_20261119_1432_cd34`
```

## `memory.md` 编写规范

- 只记录**可复用**的经验，不记流水账。
- 每条记忆应包含：触发场景 → 踩到的坑 → 正确做法。
- 已固化的结论应与代码、`项目总方案以及框架.md` 保持一致；出现冲突时以最新验证结果为准，并同步修正。
