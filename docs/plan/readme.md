# plan — 执行计划目录

存放「**怎么做**」的执行计划。与 `docs/specs/` 的分工：

- `docs/specs/项目总方案以及框架.md` —— **目标态**：项目要做成什么样（为什么做、做成什么）
- `docs/plan/` —— **路径**：从现状走到目标态的具体步骤

## 谁写

由**主理人（Manager Agent）**编写与维护。

Subagent 可以读取计划、按计划执行，但**不自行修改计划文件**；执行中发现计划站不住脚，回报主理人修订，不擅自改道。

## 文件命名

```
YYYY-MM-DD-<主题>.md
```

示例：`2026-11-19-文档骨架初始化.md`

一个主题一份文件，不做「大杂烩计划」。跨天的长计划沿用同一份文件、按日期追加进展，不拆散成多份。

## 单份计划的结构

| 章节 | 必填 | 说明 |
| --- | --- | --- |
| 目标 | ✅ | 一句话说明这份计划要达成什么 |
| 验收标准 | ✅ | 可观测、可判定的完成条件，不接受「基本完成」这类模糊表述 |
| 任务分解 | ✅ | 每项任务的执行者、前置依赖、产出物、预计耗时 |
| 风险与回滚 | ✅ | 可能踩的坑，以及失败后如何退回上一步 |
| 进展记录 | ⬜ | 执行中追加，只增不改，保留历史痕迹 |

## 状态与生命周期

| 标记 | 含义 |
| --- | --- |
| ⬜ 未开始 | 已立项未动工 |
| 🚧 进行中 | 正在执行 |
| ✅ 已完成 | 验收通过，计划结束 |
| ⏸ 挂起 | 因外部依赖暂停，需写清等什么 |
| ❌ 废弃 | 被新计划取代，注明取代者文件名 |

计划完成后**不移除**，就地标 ✅ 保留，作为决策依据的历史。真正失效的，标 ❌ 并写明取代者。

## 红线

- 不在计划文件里写进度流水（那是 `项目进度.md` 的职责），只写「怎么走」与「走到哪」
- 不出现无验收标准的计划
- 不因为赶时间跳过「风险与回滚」
