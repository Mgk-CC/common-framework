# output — 交付产物目录

存放**最终交付物**：报告、生成的文件、打包结果。只放成品，不放过程。

## 什么能进 output

- 可直接交给下游（甲方 / 上级 / 下一个环节）的成品
- **验收留证**：关键验收节点的时间、执行的命令、截图、日志摘要

## 什么不能进 output

| 内容 | 应该放哪 |
| --- | --- |
| 草稿、中间版本 | `temp_text/` 或 `data/temp/` |
| 原始输入数据 | `data/core/` |
| 临时调试文件 | 直接用完即删，不进任何目录 |

## 组织方式

```
output/<YYYY-MM-DD>-<主题>/
├── manifest.md      # 必须存在
└── <产物文件...>
```

**一次交付一个子目录**，每个子目录内必须有一份 `manifest.md`：

```markdown
# <主题> 交付说明

- 交付时间：2026-11-19 15:20
- 交付人：<主理人 / 某 Agent>　会话 ID：<sess_xxx>
- 验收人：<老大>　验收结论：✅ 通过

## 产物清单

| 文件 | 说明 |
| --- | --- |
|  |  |

## 生成方式

> 用什么命令 / 脚本生成，保证可复现

## 来源数据

> 依赖 data/core 下哪些文件，及其版本或日期
```

## 红线

- **产物只读**：交付后不手改产物。要改就回到 `data/core` 源头修数据、重跑生成流程，产出新版本
- **产物与 manifest 同目录**：没有 manifest 的交付视为未完成
- **同名不覆盖**：重复交付用 `-v2` / 日期区分，旧版本保留以便追溯
- 不上传含敏感信息的产物；必须交付时先脱敏，并在 manifest 中标注
