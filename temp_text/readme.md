# temp_text — 临时文本中转站

存放**一次性文本**：抓取的网页正文、OCR 结果、粘贴的原始材料、Agent 的中间草稿。

这是工作区的「草稿纸」，不是数据仓库。

## 与 `data/temp/` 的区别

| 目录 | 内容 | 是否可重建 |
| --- | --- | --- |
| `temp_text/` | 人读的文本片段：网页正文、原始材料、中间稿 | 部分可，依赖来源仍能回溯 |
| `data/temp/` | 程序中间数据：缓存、分片、中间表 | 100% 可重建 |

判断口径：**是给程序吃的还是给人看的**——变量、JSON、中间表进 `data/temp/`；一段话、一份正文、一个草稿进 `temp_text/`。

## 文件命名

```
YYYYMMDD-<来源>-<主题>.md | .txt
```

示例：`20261119-web-某标准文档正文.md`、`20261119-ocr-扫描件第3页.txt`

## 生命周期

- **用完即删**：任务验收后，由执行者主动清理自己产生的文件（只删自己建的，不动别人的）
- 超过 **7 天**的文件视为可清理
- 不做备份、不做版本管理
- **这里不放唯一副本**：任何有长期价值的东西都不能只存在于此

## 转正规则（重要）

如果某段临时文本被**引用超过 2 次**，说明它已经是真数据，必须转正：

- 作为正式输入数据 → 沉淀进 `data/core/`
- 作为规格依据 → 引用进 `docs/specs/` 相关文档

## 红线

- 不把 `temp_text/` 当资料库囤积
- Agent 清理时严格限定在本次任务自己创建的文件，绝不批量删除整个目录
