# data/core — 正式输入数据（唯一真源）

存放项目的**正式输入数据**：程序运行所依赖的、有长期价值的原始数据。

**这里的文件是唯一真源。** 产物不对，回这里改数据、重跑；不手改 `output/`。

## 谁有权写

| 角色 | 权限 |
| --- | --- |
| 主理人 | ✅ 可写入（新增版本、登记来源） |
| Subagent | 👁 **只读**，严禁修改、重命名、删除 |

需要新数据时，由 Subagent 提出、主理人落盘。

## 从收件箱转正

`data/inbox/` 中来源**不可重现**的文件（甲方口径、一次性导出、别人手发），必须转正到这里：

1. 放入对应数据集目录
2. 在 `_source.md` 写清来源、获取方式、获取时间、覆盖范围
3. 在 `data/inbox/<原目录>/_inbox.md` 把状态改为 `已转正`

## 不可变性

- 文件**落盘即冻结**，发现数据错了不要原地改
- 修正方式：新增一个版本（文件名带版本或日期），并在 `_source.md` 的变更记录里写清改了哪条、为什么
- 旧版本保留，便于追溯"当时为什么得出那个结论"

## 组织方式

```
data/core/
├── readme.md
├── _source.md                  # 数据来源台账（必须存在）
└── <数据集名>/
    ├── _source.md              # 该数据集的来源与校验
    └── <数据文件...>
```

每个数据集目录内配一份 `_source.md`：

```markdown
# <数据集名>

- 来源：<谁给的 / 从哪个系统导出的 / 哪个网址>
- 获取时间：2026-11-19 14:00
- 获取方式：<命令或操作步骤，保证其他人能复现>
- 覆盖范围：<时间区间、条数、口径>
- 校验：<行数 / 文件大小 / 校验和>
- 已知问题：<缺哪些字段、哪些行可疑>

## 变更记录

| 日期 | 版本 | 变更内容 | 变更人 |
| --- | --- | --- | --- |
| 2026-11-19 | v1 | 首次导入 | 主理人 |
```

## 红线

- 不放临时数据、中间结果、交付产物（分别属于 `data/temp/`、`output/`）
- 不放程序代码、脚本
- 不在无来源登记的情况下塞入文件
- 大文件（单文件 > 10MB）入库前先确认是否改用 Git LFS 或移出仓库
- 含个人信息 / 密钥的数据必须先脱敏再落盘
