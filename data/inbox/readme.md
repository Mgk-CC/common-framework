# data/inbox — 收件箱（外来文件落地区）

**所有从外部拿进来的文件，一律先落这里。**

下载的 Excel、甲方发的压缩包、API 导出的 CSV、爬下来的 PDF —— 不允许散落在工作区根目录、`src/`、`temp_text/` 或随手一个临时文件夹。

## 为什么有它

过去的做法是「拉下来就用，用完不管」，结果工作区堆满来历不明的文件：不知道谁拉的、从哪拉的、还能不能重新拿到、删了会不会出事。

收件箱把外来物圈在一个固定区域，让每一个都有 **主人、台账、删除时限**。

## 四条硬规则

1. **一次外来物 = 一个子目录**，命名 `YYYYMMDD-<来源>-<用途>`
2. 子目录内**必须**有 `_inbox.md`
3. 处理完必须写**终态**，三选一：`已入库` / `已转正` / `已清理`
4. 没写终态 = 任务没做完

```
data/inbox/
└── 20261119-某局导出-月度统计/
    ├── _inbox.md
    └── 月度统计.xlsx
```

## `_inbox.md` 模板

```markdown
# <来源>-<用途>

- 拉取人：<主理人 / Agent 名>　会话 ID：`sess_xxx`
- 拉取时间：2026-11-19 14:00
- 来源：<网址 / 接口 / 谁发来的 / 哪个系统导出>
- 获取命令：<能照抄复现的命令或操作步骤；「手动下载」要写明路径>
- 用途：<为什么要这个文件，支撑哪个计划>
- 覆盖范围：<时间区间、条数、口径>
- 校验：<行数 / 文件大小 / 校验和>
- 状态：待处理

## 处理记录

- 2026-11-19 14:30 <做了什么：导入了哪张表 / 转正到哪个目录 / 直接删除>
```

## 终态判定（照这张表走，别自己发明）

| 来源能否重现 | 处理动作 | 原始文件去留 | 终态 |
| --- | --- | --- | --- |
| **能**（有 URL、API、固定导出路径） | 抽取入库到 `data/db/` | **删**，台账里留下载指令以便重取 | `已入库` |
| **不能**（甲方口径、一次性导出、别人手发） | 转正进 `data/core/`，登记 `_source.md` | **保留**在 core | `已转正` |
| 只是看一眼，不入库也不留正 | 把结论写进 `docs/specs/` 或 `memory.md` | **删** | `已清理` |

**判定口诀：能重现的删，不能重现的转正。不允许「先放着，以后再说」。**

## TTL 与巡检

- 未写终态的收件目录，存在超过 **3 天**视为异常，必须立即处理或写明挂起原因
- 终态为 `已清理` 的目录，可整目录删除
- 巡检命令（揪出所有没收尾的）：

```bash
rg --files-without-match "状态：已" data/inbox/*/_inbox.md
```

## 红线

- 不把收件箱当资料库长期囤积
- 不直接改原始文件内容；要改就另存新版本并写明原因
- 不在其中存放密钥、未脱敏的个人信息
- 不删他人的收件目录（只清理自己建的）
