# log — 运行日志目录

存放 Agent / 程序运行时产生的日志：**机器怎么跑的**——执行了什么命令、输出什么、报了什么错、耗时多久。

机器写，人只读。

## 与 `项目进度.md` 的分工

| | 记什么 | 谁写 |
| --- | --- | --- |
| `log/` | 机器轨迹：命令、输出、异常栈、耗时 | 程序 / Agent 自动写 |
| `docs/specs/项目进度.md` | 人的决策：谁在什么时间完成了什么，对应哪个会话 | 主理人 / Subagent |

两者靠 **时间 + 会话 ID** 对齐。排查问题的路径是固定的：先在 `项目进度.md` 定位到某次会话与时间点，再进 `log/` 看那次会话的完整细节。

## 文件命名

```
YYYY-MM-DD.log              # 当天单文件，单 Agent 串行场景
YYYY-MM-DD-<agent>.log      # 多 Agent 并行时按 Agent 分文件
```

## 写入规则

- **只追加，不覆盖**：重启不重写历史
- 每条日志至少包含：时间戳、会话 ID、Agent 名、级别（`INFO` / `WARN` / `ERROR`）
- 禁止手工编辑日志内容；需要在某条日志上做批注，去 `项目进度.md` 里写
- **落盘前脱敏**：密钥、token、账号、个人信息一律不得写入日志

## 保留与清理

- 常规日志默认保留 **14 天**，过期归档或删除
- `ERROR` 级别、以及关键验收节点的日志，复制到 `output/<日期>-<主题>/` 归档留证（详见 `output/readme.md`）
- 日志体积可能很大，若后续建立版本库，必须在 `.gitignore` 中排除 `log/`

## 红线

- 不把 log 当唯一的错误账本：真正的坑要总结进 `docs/specs/memory.md`，日志只是原始证据，会被清理
- 不同 Agent 不共用同一个日志文件（并行写入会串行化、丢行），一律按 Agent 分文件
